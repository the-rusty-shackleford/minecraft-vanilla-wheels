# D-0016 — Garage door inside and outside

Rusty reported that garage doors could not reverse their inside/outside direction.
They acknowledged four-direction placement: the first panel's outside faces its
placer and coplanar extensions inherit it. They then withdrew the separate
chaining report, explicitly retaining the need to fill the complete rectangle.
This authorizes local development, not another release or deployment.

Retain D-0015's full rectangular assembly, top-down or bottom-up construction,
redstone control, obstruction handling and interaction messages. This decision
extends its placement orientation only. No wrench rotation gesture is added.

The saved horizontal width axis remains. An additional `reversed` boolean gives
exactly four possible outside directions; default false preserves old world
palettes without a migration or a forced rebuild. Legacy X faces north; legacy Z
faces east, matching the renderer's original quarter-turn. Rotation and mirror
operations transform the derived direction while retaining the root property.

Edge placement and floor placement beside an existing coplanar door inherit its
outside. Bridging two oppositely facing doors is refused without item consumption
instead of silently flipping either. Discovery connects only matching facings.
Clicking the front/back to start a separate parallel door uses the player's
direction, since that panel is not in the existing door's plane.

The renderer rotates around the full assembly's centre when reversed, retaining
its world bounds, collision and controller coordinates. Lighting samples the
actual outside. No new recurring world scans, vehicle art, driving behavior or
vehicle protocol change is introduced. All peers still need matching mod builds.

The new real-server regression first failed against 1.9.0: four actual player
placement headings produced only two distinct states. Expanded coverage uses real
server game-mode interactions, top-down extension, all four redstone/collision
orientations, vanilla palette serialization, rotations and mirrors. The client
booth places the first panel using actual client packets and captures both sides
of all four resulting doors. See the orientation verification record.
