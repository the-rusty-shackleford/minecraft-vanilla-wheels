# D-0044 — A ring equals itself

Rusty, 2026-10-21: he put his keyring into a Warehouse Manager "and now it won't let me take it back
out". The warehouse's index sends each kind to the client and takes back the kind clicked by item and
components (`ItemStack.isSameItemSameComponents`). The ring's `keyring_keys` component was a bare
`List<ItemStack>`, and `ItemStack` has no value equality: two copies of one ring compared equal only
while they shared the list object, never once one had crossed the network or a save. So the clicked
ring matched nothing, the count read 0 and the click did nothing. Anything else that compares rings by
item and components missed the same way.

**Decision**: the component's value is `Keyring.Keys`, a record over the list whose `equals` and
`hashCode` are vanilla's own for a box's or a bundle's contents (`ItemStack.listMatches`,
`hashStackList`). Its codecs are the plain list's mapped onto the record, so a ring saved or sent by
1.18.1 reads the same and nothing on disk or on the wire changes; network 10 stands. The Warehouse
Manager no longer takes a ring at all (its D-0017); this makes the ring's comparison right wherever
else it is made.

**Verification**: `aRingIsTheSameRingAfterTheWireAndASave` pairs two vehicles, sends the ring through
`ItemStack.STREAM_CODEC` and through a save and parse, and asserts each is the same item with the same
components, the component maps hashing alike, and a ring with a key fewer not the same. Run once on
1.18.1's code first: it failed there at "the ring after the wire is the same ring", and only there.
